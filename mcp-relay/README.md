# mcp-relay (M1.2)

Relays the Mac's Xcode MCP server (`xcrun mcpbridge`, stdio) to consumers on
the Unraid LAN over WebSocket with bearer auth.

```
                 Unraid (this image)                                Mac Mini
   ┌────────────────────────────────────────────┐     ┌──────────────────────────────────────────┐
   │ Hermes  ──stdio(NDJSON)──► remote-stdio.mjs │     │  ~/mcp-relay/relay.mjs (launchd agent)   │
   │ pi      ──stdio(NDJSON)──► (same shim)      │ WS  │    │  Bearer auth on upgrade             │
   │                                             │ ◄──► │    │  1 connection = 1 child            │
   │ env: MCP_RELAY_URL + MCP_RELAY_KEY          │     │    ▼                                     │
   └────────────────────────────────────────────┘     │  xcrun mcpbridge ──► Xcode (running app)  │
              VLAN only (no internet exposure)        └──────────────────────────────────────────┘
```

Transport contract (probe-verified, `scripts/mcpbridge-probe.mjs`):
newline-delimited JSON-RPC 2.0, **one line per frame on both ends**, in both
directions. The relay and the shim are transparent line pipes; mcpbridge
needs **no env vars** (it auto-detects the running Xcode).

## Files

| File | Runs where | Role |
|---|---|---|
| `relay.mjs` | Mac (launchd) | WS server; per-connection `xcrun mcpbridge` child; child stderr → log file only |
| `remote-stdio.mjs` | Unraid (any node host/container) | stdio MCP ↔ WS shim; env config only |
| `install.sh` | Mac | node check, `npm ci`, config + key generation, launchd agent |
| `test/` | anywhere (node ≥ 20) | `node --test` suite against `test/fake-mcpbridge.mjs` (no Xcode, no LAN) |

## Security model

- **Loopback by default.** The relay binds `127.0.0.1` unless `install.sh --bind <IP>`
  is used explicitly. VLAN exposure is a deliberate, visible decision.
- **Bearer key on the WS upgrade.** `Authorization: Bearer <key>` (timing-safe
  comparison); failure → HTTP 401 and **no child process is spawned**. The key
  is 32 random bytes (base64url), generated by `install.sh`, stored in
  `~/Library/Application Support/mcp-relay/config.json` (mode 600), and
  printed **once** at creation.
- **No internet exposure.** No public domain, no reverse-proxy route, no
  `0.0.0.0` default. The relay is reachable only from the LAN/VLAN where the
  Mac sits.
- **No secrets in the repo.** This repo contains placeholders only. Real
  values live in the Mac's generated `config.json` and the Unraid host `.env`.
- **Child stderr never enters the MCP stream.** It is appended to
  `~/Library/Logs/mcp-relay.stderr.log` only.
- **TLS is out of scope (future hardening).** The wire is unencrypted
  `ws://` inside a trusted VLAN. If the network is ever untrusted, put
  `stunnel` (or a TLS-terminating proxy) in front of the relay port and point
  consumers at `wss://` — the shim already accepts `wss://` URLs.

## Mac install (one-time)

```sh
cd mcp-relay            # repo checkout on the Mac
./install.sh            # loopback default
# or, to expose on the VLAN:
./install.sh --bind <MAC_VLAN_IP> [--port N]
```

`install.sh` prints the key once and a ready-to-paste consumer env snippet.
Xcode must be running for tools to be available; with Xcode closed,
`initialize` returns a JSON-RPC error and the child exits (clean failure,
surfaced to the consumer as a WS close with code 4500).

Re-run is idempotent: existing config (and key) are kept; the launchd agent
`com.pi.mcp-relay` (KeepAlive + RunAtLoad) is rewritten and reloaded. Console
log: `~/Library/Logs/mcp-relay.console.log`.

## Consumer wiring

### (a) Hermes CLI — `mcp_servers` entry

```toml
[mcp_servers.xcode]
command = "node"
args = ["/path/to/pi-sandbox/mcp-relay/remote-stdio.mjs"]
env = { MCP_RELAY_URL = "ws://<mac-host>:3129", MCP_RELAY_KEY = "<key from Mac config.json>" }
```

(Use the real values from the host `.env` / Mac config — never commit them.)

### (b) pi (in the pi-sandbox image)

pi 1.5.2 registers MCP servers in `mcp.json` (user-level:
`${PI_CODING_AGENT_DIR:-~/.pi/agent}/mcp.json`; project-level: `.pi/mcp.json`).
Supported transports: **stdio** (`command`/`args`/`env`) and **streamable HTTP**
(`url`/`headers`) — no SSE, no native WS transport, hence the stdio shim.

The image's entrypoint (`config/entrypoint.sh`) upserts the `xcode` entry into
`${PI_CODING_AGENT_DIR}/mcp.json` on startup **when** `MCP_RELAY_URL` and
`MCP_RELAY_KEY` are set to real (non-placeholder) values:

```json
{
  "mcpServers": {
    "xcode": {
      "command": "node",
      "args": ["/opt/mcp-relay/remote-stdio.mjs"],
      "env": {
        "MCP_RELAY_URL": "${MCP_RELAY_URL}",
        "MCP_RELAY_KEY": "***"
      },
      "description": "Xcode tooling relayed from the Mac (DocumentationSearch, project state, builds)."
    }
  }
}
```

Equivalent manual setup inside a session host: `pi mcp add xcode --env
MCP_RELAY_URL='${MCP_RELAY_URL}' --env MCP_RELAY_KEY='${MCP_RELAY_KEY}' --
node /opt/mcp-relay/remote-stdio.mjs`, then `/reload`.

## Tests

```sh
cd mcp-relay
npm install            # ws (package-lock.json committed; install.sh uses npm ci)
npm test               # node --test — fully offline, fake mcpbridge, ephemeral ports
```

Coverage: bearer auth (401 + no child spawned), WS↔stdio round-trip,
client-disconnect → child SIGTERM, child-exit → WS close 4500 with exit code +
last stderr line, concurrent-connection isolation (distinct pids), shim
round-trip, relay-death propagation, missing-env failure.
